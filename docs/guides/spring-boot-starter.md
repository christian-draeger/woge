# Configure Woge with Spring Boot

The Woge starter configures shared policy and selects one server adapter. You still write normal
Spring routes, choose normal HTTP methods and use the browser as a browser.

For a complete runnable page first, use the [Spring Boot quickstart](quickstart-spring-boot.md).

## Add one web stack

For WebFlux, an application uses these three dependencies:

```kotlin
dependencies {
    implementation("dev.woge:woge-spring-boot-starter:<version>")
    implementation("dev.woge:woge-spring-webflux:<version>")
    implementation("org.springframework.boot:spring-boot-starter-webflux")
}
```

For Spring MVC, choose the matching pair instead:

```kotlin
dependencies {
    implementation("dev.woge:woge-spring-boot-starter:<version>")
    implementation("dev.woge:woge-spring-mvc:<version>")
    implementation("org.springframework.boot:spring-boot-starter-web")
}
```

The general Woge starter deliberately includes neither MVC nor WebFlux. This makes it safe to replace
the transport adapter without pulling two server stacks into the application.

## Connect a page to familiar routes

Declare your `PageUseCase` as a Spring bean. Boot discovers it for diagnostics and provides a
`WogeWebFluxHandlers` factory with the configured request-context and deferred-work policy:

```kotlin
@Configuration(proxyBeanMethods = false)
class ProjectRoutes {
    @Bean
    fun routes(
        projectPage: ProjectPage,
        handlers: WogeWebFluxHandlers,
    ): RouterFunction<ServerResponse> {
        val page = handlers.page(projectPage, ProjectRoute)
        val patches = handlers.deferred(projectPage, ProjectRoute.webFluxInput())

        return coRouter {
            GET(ProjectRoute.path, page::handle)
            GET("${ProjectRoute.path}/woge-patches", patches::handle)
        }
    }
}
```

`ProjectRoute` is generated by Woge's KSP processor from `@WogeRoute("/projects/{project}")` on
`ProjectInput`. The paths stay visible in your router because they are application behavior; the
generated route reads the values and builds links. See [Typed page routes](typed-routes.md).

MVC uses the same page object through `WogeSpringMvcHandlers` and `SimpleUrlHandlerMapping`. See the
[Spring MVC adapter guide](spring-mvc-adapter.md) for its short route example and Servlet lifecycle.

HTML components are normal Kotlin functions or values called by the page. They do not need an
annotation or Spring component scan.

## Tune only measured limits

Defaults work without configuration. When measurements show a need, Spring's normal duration syntax
and IDE metadata are available:

```yaml
woge:
  mvc:
    async-timeout: 60s
  deferred:
    max-concurrency: 6
    region-timeout: 2s
```

Deferred limits apply per patch-stream request. `mvc.async-timeout` bounds a Servlet page or patch
response and should exceed the region timeout. Invalid non-positive values fail while the application
context starts.

| Property | Default | Meaning |
| --- | --- | --- |
| `woge.adapter` | `auto` | Select `mvc` or `webflux`; auto requires one web stack. |
| `woge.deferred.max-concurrency` | `8` | Maximum concurrent regions per patch response. |
| `woge.deferred.region-timeout` | `30s` | Maximum time for one region. |
| `woge.mvc.async-timeout` | `60s` | Maximum Servlet response lifetime. |

The configuration processor publishes `woge.*` IDE metadata. Boot's failure report explains missing
adapter dependencies, mixed stacks, a mismatched application type and non-positive limits. Servlet
async support is checked when a request starts; enable it on the servlet and every filter in its chain.

## Override shared policy

Declare an application bean of the matching type to replace `WogeObserver`, `FailurePages`,
`AssetUrls`, `WogeApplicationCatalog`, `WogeRuntimeInfo`, either request-context factory, or either
handler factory. Defaults use `@ConditionalOnMissingBean`; an application bean wins without enabling
bean-definition overriding.

To replace the asset resource mapping, name your `WebMvcConfigurer` bean `wogeSpringMvcAssets`, or
name your `WebFluxConfigurer` bean `wogeWebFluxAssets`. Other Spring configurers do not disable the
Woge asset mapping. Build-generated assets remain normal Spring resources under `/_woge/assets/**`,
with immutable caching and 404 for unknown hashes.

## Use Spring locale, identity and sessions

Default contexts use Spring's resolved locale, not a second interpretation of `Accept-Language`.
MVC respects `LocaleResolver`; WebFlux respects the exchange's `LocaleContextResolver`.

Spring owns sessions. Read `request.getSession(false)` in an MVC input/context factory, or await
`request.exchange().session` in a WebFlux factory, and copy only the facts needed by portable code.
Do not retain a Servlet request, exchange or mutable session in `RequestContext`. Woge has no parallel
session store and does not create sessions for ordinary page requests. Spring Security can use its
normal session and CSRF token storage; the shared security-form tests cover expired sessions.

## Use the default form-action security

The default `WebFluxRequestContextFactory` or `SpringMvcRequestContextFactory` creates anonymous
request snapshots. Action bindings allow normal same-origin browser forms: they compare Origin with
the request origin, or accept `Sec-Fetch-Site: same-origin` when Origin is absent or `null`. Other
unsafe requests receive 403 before form decoding. This CSRF check is not authentication or domain
authorization.

A Spring Security application should expose its own matching factory bean to translate its principal
and verified token decision; the built-in `@ConditionalOnMissingBean` default backs off. Behind a
TLS-terminating proxy, set `server.forward-headers-strategy=framework` and trust forwarded headers
only from the proxy, so the request origin matches the browser's public URL.

## Connect metrics, traces or development tools

When Micrometer's `ObservationRegistry` is present as a bean, Boot installs a Woge observation bridge.
For example, add Spring Boot Actuator and configure its normal observation/tracing handlers. The
bridge uses the registry that Boot configures; Woge does not create a second registry or exporter.
Boot's Micrometer OpenTelemetry tracing bridge can export these observations without a direct
OpenTelemetry dependency in Woge. Applications without a registry keep the no-op observer.

Observations are named `woge.operation`, with only `operation` and terminal `outcome` as metric tags.
Request/correlation IDs, page epochs, region and patch IDs are high-cardinality trace attributes only.
Started and finished events are paired by observation ID, even when coroutines change threads.
No thread-local observation scope is opened across suspended work. Registry handlers measure the
start-to-stop interval; a custom observer can record the exact semantic event duration instead.

Your own `WogeObserver` bean replaces the bridge. Micrometer is optional in the autoconfigure module;
Spring, Micrometer, OpenTelemetry and Reactor stay out of portable core modules. See the
[semantic observability guide](semantic-observability.md) for the portable events and cardinality rules.

## Resolve mixed Spring stacks

With one stack, `woge.adapter=auto` needs no property. If both Spring MVC and WebFlux are on the
classpath, Woge refuses to guess. Select the intended adapter and make Boot create the same web
application type:

```yaml
woge:
  adapter: webflux
spring:
  main:
    web-application-type: reactive
```

At startup, `WogeRuntimeInfo` and one log line report the selected adapter, patch protocol and runtime
versions, and the number of page/deferred use-case beans. A missing adapter error names the dependency
that must be added.

See [the WebFlux adapter guide](spring-webflux-adapter.md) for response and cancellation behavior and
[the Spring MVC adapter guide](spring-mvc-adapter.md) for Servlet threading and disconnect behavior.
[ADR 0029](../adr/0029-neutral-spring-boot-starter-and-explicit-adapter-selection.md) records the
dependency and ambiguity tradeoffs.

For deployment timing, disconnect cleanup and operational settings, see
[streaming behind proxies](streaming-behind-proxies.md).

## Render identities for enhanced pages

Boot provides the shared render secret to MVC and WebFlux handler factories. Set
`woge.render-identity.secret` from your secret store to the Base64 encoding of at least 32 random
bytes, shared across all instances. An unset value generates a random process-local secret and a
warning: safe for development, but not for continuity across restarts or multiple instances.
Configured invalid values fail startup. Woge never logs the secret. See [live regions](live-updates.md)
for the host-owned render session and one-route live binding.
